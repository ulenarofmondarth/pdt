# Internationalisation

All message strings are defined in `messages/en.json`, the base locale. Never hardcode text that a user will see; add a message and use it through `m['...']()` from `@i18n/messages.js`.

Messages are compiled by [paraglide](https://inlang.com/m/gerre34r/library-inlang-paraglideJs) when the project is built or tested. The locales are listed in `project.inlang/settings.json`.

## Translations

| Locale | File | Status |
| --- | --- | --- |
| English | `messages/en.json` | Base locale |
| German | `messages/de.json` | Machine translated, unreviewed |
| French | `messages/fr.json` | Machine translated, unreviewed |
| Spanish | `messages/es.json` | Machine translated, unreviewed |

When you add or change a message in `en.json`, add or update it in every other locale in the same change. A unit test (`tests/unit/messages.test.ts`) fails if a locale is missing a message, has one that English does not, leaves one empty, or does not keep the same `{placeholders}`.

To add a locale, add its code to `locales` in `project.inlang/settings.json` and create `messages/<code>.json` with every message translated.
